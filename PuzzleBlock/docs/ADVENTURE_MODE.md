# 어드벤처 모드 기획

[GAME_DESIGN.md](GAME_DESIGN.md) 12장 제안과 [TASKS.md](TASKS.md) T-08을 구체화한 문서입니다.

## 1. 목적

클래식 모드는 끝없이 점수를 쌓는 구조라 판마다 목표가 같습니다. 어드벤처 모드는 **스테이지마다 다른 목표와 시작 보드**를 주어 다음을 보완합니다.

- **변동 목표**: "보석 3개를 모아라", "12수 안에 4줄" 처럼 판마다 풀어야 할 문제가 달라집니다.
- **짧은 성취**: 1~3분 안에 끝나는 스테이지를 깨고 별을 모으는 단기 목표.
- **학습 곡선**: 초반 스테이지가 줄 맞추기·콤보·보석을 차례로 가르칩니다(원칙 "설명 없는 첫 판").

## 2. 규칙

| 항목 | 규칙 |
|---|---|
| 보드·블록·배치 | 클래식과 동일. 블록 생성은 적응형 생성기(순차 배치 보장 포함) 사용 |
| 시작 보드 | 스테이지마다 미리 채워진 블록 배치. 일부 블록에는 보석이 박혀 있음 |
| 목표 | `score` 점수 N점 달성 · `lines` N줄 지우기 · `gems` 보석 N개 모으기 |
| 이동 제한 | 스테이지별 최대 배치 횟수. 0이면 무제한 |
| 보석 수집 | 보석이 있는 칸이 줄 클리어로 지워지면 1개 수집 |
| 성공 | 목표를 달성하는 즉시 스테이지 클리어 |
| 실패 | 이동 횟수를 다 쓰거나, 남은 블록을 놓을 곳이 없을 때. 부활 없음 |
| 별 | 사용한 이동 수로 결정. `stars: [3성 최대, 2성 최대]` 이하면 해당 별, 그 외 1성 |
| 해금 | 스테이지를 클리어하면 다음 스테이지 해금 |
| 기록 | 스테이지별 최고 별 수를 로컬(`user://adventure_progress.json`)에 저장. 랭킹에는 반영하지 않음 |

## 3. 스테이지 데이터 형식

`scripts/adventure_data.gd`의 `STAGES` 상수에 정의합니다. 한 스테이지는 다음 필드를 가집니다.

```gdscript
{
	"id": 5,
	"name": "첫 보석",
	"goal": {"type": "gems", "target": 2},   # score | lines | gems
	"moves": 15,                             # 0 = 무제한
	"stars": [8, 12],                        # 3성·2성 기준(사용 이동 수)
	"layout": [                              # 8줄 × 8칸, 위에서 아래로
		"........",
		...
		"rrRr.rrr",                          # 소문자 = 블록, 대문자 = 보석 박힌 블록
		"ccc.cCcc",
	],
}
```

- 색 문자: `r` 빨강, `b` 파랑, `y` 노랑, `p` 보라, `o` 주황, `g` 초록, `c` 시안, `k` 분홍, `.` 빈칸
- 검증 규칙(테스트로 확인): 8×8 크기, 시작 시 가득 찬 줄 없음, `gems` 목표 수 ≤ 배치된 보석 수

## 4. 스테이지 구성 (20개)

| 구간 | 스테이지 | 가르치는 것 |
|---|---|---|
| 입문 | 1~3 | 점수 목표, 줄 목표, 콤보 |
| 기본 | 4~7 | 거의 찬 줄 활용, 첫 보석 |
| 응용 | 8~14 | 흩어진 장애물, 모서리 보석, 이동 제한 속 점수 |
| 숙련 | 15~20 | 보석 다수 + 빡빡한 이동 제한 |

각 스테이지의 난이도와 별 기준은 탐욕 봇 자동 플레이(`tests/test_adventure.tscn`)의 결과를 보고 조정합니다. 모든 스테이지는 봇이 최소 한 번은 깰 수 있어야 합니다.

## 5. 화면

- **홈 화면**: "오늘의 챌린지" 옆에 "어드벤처" 버튼.
- **스테이지 선택**: 4×5 격자. 스테이지 번호, 별(★☆), 잠김 표시. 뒤로 가기로 홈 복귀.
- **게임 중 헤더**: 제목에 `STAGE N`, 오른쪽 상자에 목표 진행(`보석 1/3`)과 남은 이동 수.
- **결과 창**: 게임오버 창을 재사용. `STAGE CLEAR!` / `STAGE FAILED`, 별, 목표 요약, [다음 스테이지] [다시 도전] [스테이지 선택].

## 6. 로그

`game_start`에 `mode: "adventure"`, `stage_id` 추가. 결과는 `stage_result` 이벤트(`stage_id`, `cleared`, `stars`, `moves_used`, `score`, `reason`)로 남깁니다. 스테이지별 클리어율과 실패 원인은 난이도 조정의 근거가 됩니다.
