# 점수 규칙과 서버 검증

클라이언트(GDScript)와 서버(JS)가 같은 규칙으로 점수를 계산하도록 정리한 명세입니다. [TASKS.md](TASKS.md) T-11의 결과물입니다.

## 1. 규칙의 원본과 공유 방법

| 항목 | 원본 위치 | 서버로 전달 |
|---|---|---|
| 블록 모양·분류 | `scripts/block_data.gd` `SHAPES` | `tools/block_rules.json` `shapes` |
| 블록 기본 가중치 | `scripts/block_data.gd` `SHAPE_BASE_WEIGHTS` | `base_weights` |
| 점수 상수 | `scripts/main.gd` `LINE_SCORE_BASE` 등 | `scoring` |
| 부활 최대 제거 칸 | `scripts/board.gd` `REVIVE_MAX_CELLS` | `revive_max_cells` |
| 챌린지 시드 | `main.gd` `hash("block-daily-" + 날짜)` | `daily_seed_prefix` |

규칙을 바꾸면 반드시 다시 내보냅니다.

```bash
Godot_v4.7.2-stable_win64_console.exe --headless --path . res://tools/export_rules.tscn
```

내보낸 JSON에는 Godot 엔진이 직접 만든 **검증용 샘플**(문자열 해시, 난수 출력, 날짜별 챌린지 세트 40개)이 들어 있습니다. 서버 쪽 포팅(`tools/block_replay.js`)이 엔진과 똑같이 동작하는지 이 샘플로 확인합니다.

## 2. 점수 공식

| 항목 | 공식 |
|---|---|
| 배치 | 놓은 칸 수 |
| 라인 클리어 | `trunc(10 · L² · (1 + 0.45·C)) + trunc(15·C + 5·C²)` |
| 퍼펙트 클리어 | 클리어 후 보드가 비면 `round(300 · (1 + 0.45·C))` 추가 |
| 콤보 | 줄을 지우면 `C += 1`, 유예 3으로 초기화. 못 지우면 유예 −1, 0이 되면 `C = 0` |
| 콤보 피버 | `C ≥ 5`이면 라인 클리어 점수(위 두 항의 합)를 `trunc(× 1.5)` |

`L`은 한 번에 지운 줄 수(가로+세로), `C`는 이번 클리어를 포함한 콤보 수입니다. 부활은 점수를 주지 않습니다. 어드벤처 점수는 서버에 제출하지 않습니다.

## 3. 배치 기록(play log) 형식

게임오버 때 클래식·챌린지 점수와 함께 `log` 배열을 보냅니다. 항목은 발생 순서대로 기록합니다.

| 항목 | 형식 | 의미 |
|---|---|---|
| 시작 보드 | `["s", cell, ...]` | 클래식 시작 패턴으로 미리 채운 칸 번호(`x + y·8`). 있으면 항상 첫 항목 |
| 지급 | `["d", id, id, id]` | 트레이 3칸에 지급된 블록(칸 순서) |
| 배치 | `["p", id, x, y]` | 블록을 격자 좌표 `(x, y)`(블록 경계의 왼쪽 위)에 배치 |
| 부활 | `["r", cell, ...]` | 부활로 지운 칸 번호(`x + y·8`) |

## 4. 서버 검증 (`POST /api/block-game/score`)

서버는 기록을 처음부터 다시 두면서 다음을 확인합니다. 하나라도 어기면 `400`과 `reason`을 돌려주고 점수를 저장하지 않습니다.

- 시작 보드는 첫 항목에서만, 오늘의 챌린지에서는 불가. 칸 1~22개, 중복 없음, 채운 뒤 가득 찬 줄이 없어야 함(점수 없음)
- 지급은 트레이가 빈 뒤에만 가능하고, 존재하는 블록 3개여야 함
- 배치는 현재 트레이에 남은 블록만, 보드 안의 빈칸에만 가능
- 부활은 판당 1회, 남은 블록을 어디에도 놓을 수 없을 때만, 차 있는 칸만, 최대 16칸
- 다시 계산한 점수가 제출한 점수와 정확히 같아야 함
- **오늘의 챌린지**: 서버가 날짜 시드로 블록 순서를 재생성해, 모든 지급이 그 순서와 같아야 함

`REQUIRE_REPLAY_LOG = true`이면 기록 없는 제출도 거부합니다. 새 Web 빌드를 배포하기 전의 구버전 클라이언트는 점수를 등록할 수 없게 됩니다.

## 5. 한계

- **클래식 모드의 블록 지급은 검증하지 않습니다.** 적응형 생성기는 보드 상태에 따라 블록을 고르므로 서버에서 재현할 수 없습니다. 조작된 클라이언트가 원하는 블록만 받는 기록을 만들 수는 있지만, 그 기록도 규칙에 맞게 실제로 둘 수 있어야 합니다. 임의의 점수를 보내는 방식은 막힙니다.
- 부활로 지운 칸의 무작위성은 검증하지 않습니다(칸 수와 위치의 유효성만 확인).
